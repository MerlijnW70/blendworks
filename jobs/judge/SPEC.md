# Job: The asset judge

Build the judge of docs/DESIGN.md sections 3 and 4: an asset spec schema, and a command that measures a delivered asset in a sandboxed headless Blender, renders fixed views and reports pass or fail.

## Required

1. **Schema:** `schemas/asset-spec.schema.json` (JSON Schema) and `src/judge/spec.ts`, which validates a spec with zod and gives clear errors. Every field of the design's example is supported, and every rule is optional except `format`.
2. **Measuring script:** `bridge/judge/measure.py`, the judge's own script, run as `blender --background --factory-startup --disable-autoexec --python bridge/judge/measure.py -- <asset> <out.json>`. It:
   - imports the asset into an empty scene (`.glb`/`.gltf`/`.fbx`/`.obj`), or reads the data of a `.blend` with auto-run disabled;
   - measures:
     - triangles (after triangulating evaluated meshes, modifiers applied);
     - object count;
     - world-space bounds and size per axis;
     - the origin's position relative to the bounds (bottom centre, geometric centre);
     - manifoldness (non-manifold edges, boundary edges, loose parts);
     - material count and names;
     - UV presence, coverage of the 0–1 square, and overlap ratio;
     - file size.
   It writes the measurements as JSON.
3. **Renders:** `bridge/judge/render.py` renders the spec's views with a camera rig fitted to the bounds:
   - a neutral three-point light and a neutral grey background;
   - Cycles on the CPU, with fixed samples, seed and resolution (512×512 per view);
   - a contact sheet PNG of all views with labels.
4. **Command:** `src/judge/cli.ts` gives `npx blendworks judge <spec.json> <asset> [--out dir]`, which:
   - checks the Blender version is 5.2 and refuses others;
   - runs the two scripts in a sandbox: in WSL or Linux, with no network (`unshare -rn` when available, and with a timeout and a memory limit); on Windows with a timeout and a memory cap;
   - compares every rule, writing `report.json` with each rule, its measured value, its limit and pass or fail, plus a short text summary;
   - exits 0 only when every rule passes.
   It is exposed as `bin` `blendworks` in `package.json`.
5. **Malicious and broken input:**
   - a `.blend` with an embedded auto-run script must not run it (a test proves this with a file whose script would create a marker file);
   - corrupt files, huge meshes (over a configurable cap) and missing files fail cleanly, with a reason.
6. **Tests:** fixture assets generated by test setup scripts in headless Blender (not committed binaries):
   - a crate that passes;
   - one over the triangle budget;
   - one with the wrong size;
   - one with its origin at the centre instead of the bottom;
   - a non-manifold one;
   - one without UVs;
   - one with overlapping UVs;
   - a `.blend` with an auto-run script.
   Each report's measured values are worked out by hand for the simple shapes (a 1×1×0.8 box has 12 triangles, and so on). Renders are produced and are non-empty, and the contact sheet exists.

## Rules

- Follow `CONTRIBUTING.md`.
- Touch only `src/judge/`, `bridge/judge/`, `schemas/`, `test/judge*`, and `package.json` (`bin` and scripts).
- Other jobs build the bridge (`bridge/blendworks_bridge`, `src/session.ts`) and the MCP server in parallel. Rebase onto the latest main before delivering.

## Acceptance

1. `npm run check` passes with the patch applied to `main` at the commit the delivery names.
2. A test fails when the judge lets the `.blend` auto-run script run, or stops counting modifier-generated triangles.
3. The judge views the contact sheets of the passing and failing fixtures.

## Deliver

One commit; the patch from `git format-patch -1 --stdout`. Include contact sheet paths in the report. Announce its sha256 to the judge.
