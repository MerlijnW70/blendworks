# Job: Measurements that a crafted asset cannot steer

A security audit of the judge found ways an asset can pass rules it should fail, or make its verdict depend on the machine:
- The visibility sample uses a public constant seed (`bridge/judge/judge_surface.py`, `SEED = 20261027`), so a worker can put hidden filler at face indices the sample never tests.
- A second shell a few micrometres inside the first counts as visible and is not a duplicate, because rays start a large offset along the ray and duplicates must match within 1 µm.
- n-gons are tested at four triangle centres plus the largest triangle, so most of a mostly hidden n-gon escapes.
- Measuring uses the viewport depsgraph while renders use render settings (curve and metaball resolution, particle display percentage, instancer visibility in .blend files).
- Fully transparent or holdout geometry counts as visible.
- Non-finite vertices, matrices and UVs are not refused, and JSON is written with `NaN` allowed.
- Asset strings (image names, URIs, importer errors) reach `summary.txt` unescaped, so they can forge lines or carry instructions to an agent that reads the report.
- A timeout, memory cap or file lock decides the verdict, so the same asset can pass on one machine and fail on another.
Close each at its root without changing the verdict of any honest asset.

## Base

- **Base commit:** the `main` commit this spec is added in. Rebase onto the latest `main` before delivering.

## Required

1. **Unpredictable, fair sampling:** derive the visibility sample seed from the delivery set's sha256; sample stratified by area or space, and raise the full-test cap so typical assets are tested exhaustively; n-gons are tested over their full area (sampled triangles or a stratified point set), not five points.
2. **Layers:** rays start a tiny epsilon along the face normal and ignore hits on the face itself; a near-coincident-layer check flags a face whose normal ray meets another face within a tolerance relative to the asset's extent; such layers count as hidden.
3. **Render parity:** before measuring, copy render settings into the viewport settings for everything that changes geometry or visibility (subdivision and multires levels, curve resolution, metaball resolution, particle display percentage and child counts, instancer visibility), so measured and rendered geometry match; test with a .blend whose viewport and render differ.
4. **Effective visibility:** faces whose effective opacity is about zero (alpha 0, holdout, transparent BSDF) do not count as visible for triangle, shell and bounds rules; document how opacity is determined.
5. **Finite input:** refuse non-finite vertices, object matrices and UVs at load with a clear failure; write all stage JSON with `allow_nan=False`.
6. **Report hygiene:** every string that comes from the asset is stripped of control characters and newlines, quoted and capped in `summary.txt` and any text an agent reads; the report says the content is untrusted.
7. **Infrastructure is not a verdict:** a stage timeout, a memory cap hit or a file-lock wait past its bound is reported as an infrastructure error to retry, never as FAIL; bound the work of each measure stage before it runs (triangles, frames, texels) so the same asset hits the same limits on every machine.
8. **Equivalence:** every proof asset and fixture keeps its verdict; value changes caused by the fixes are listed and justified in the delivery and re-recorded only for the fixtures that changed.

## Tests

One negative test per acceptance item: a test that fails when the behaviour the item names stops holding. Say how you proved it, for example by breaking the code once and watching the test fail. Include crafted fixtures: filler at indices the old seed skipped, a 5 µm inner shell, a mostly hidden n-gon, a .blend with viewport/render differences, alpha-0 faces, NaN vertices, an image name with newlines and a fake `pass` line.

## Rules

- Follow `CONTRIBUTING.md`. Fixtures are generated by scripts, never committed as binaries.
- **Allowed files:** `src/judge/**`, `bridge/judge/**`, `test/judge/**`, `docs/**`.
- **Files shared with other open jobs:** judge-sandbox owns the sandbox and reference-policy files (`sandbox.ts`, `low_integrity.py`, `sandbox.sh`, `gpu-cache.ts`, `kernel-cache.ts`, `delivery.ts`); this job runs after it and rebases.
- **Environment and concurrency:** Blender 5.2 through `BLENDER`. At most `BLENDWORKS_JOBS` Blender processes run at once, 2 by default; do not raise it and do not run several full checks at once.
- **While working:** iterate with `npm run check:fast` and single test files. Run `npm run check` once, at the end, at low priority.

## Acceptance

1. `npm run check` passes with the patch applied to `main` at the commit the delivery names.
2. Every required item has a test that fails when its behaviour stops holding.
3. The judge re-judges every proof asset and sees unchanged verdicts, and judges the crafted fixtures and sees each fail for the stated reason.

## Deliver

One commit; the patch from `git format-patch -1 --stdout`. Announce its sha256 to the judge.
