# Job: Repair, retopology and rebake: the gate every imported or generated mesh passes

Meshes from outside Blendworks (AI generators such as TRELLIS.2, scans, downloads, other tools) typically arrive as dense triangle soup (often 50k to 500k triangles where a game asset needs 2k to 15k), with non-manifold edges, internal faces, zero-area triangles, small holes, floaters, wrong scale or orientation, no usable UVs, and lighting baked into the albedo. Production pipelines keep the dense mesh as a bake source, build a clean low-poly (retopology), unwrap it and rebake its maps. Blendworks has decimation, voxel remesh, UV tools and baking, but no command chain that turns a raw mesh into a judged, game-ready asset. Build that gate.

## Base

- **Base commit:** the `main` commit this spec is added in. Rebase onto the latest `main` before delivering.

## Required

1. **`mesh_diagnose`:** a report of every defect the judge would fail or warn on (non-manifold edges and vertices, holes with their perimeters, internal and duplicate faces, zero-area and sliver faces, floaters by size, inverted shells, self-intersections, scale and orientation guesses from bounds and a ground plane, UV state, texel density), with counts and locations, read-only.
2. **`mesh_repair`:** deterministic fixes with explicit switches: weld within a tolerance, remove internal, duplicate and degenerate faces, fill holes up to a perimeter (with flat or smooth fill), remove floaters below a size or keep the N largest shells, make normals consistent, normalise scale to a target size and orientation (up axis, forward axis, origin at bottom-centre); reports what it changed; never changes what it was not asked to.
3. **`retopo`:** a clean low-poly from a dense mesh: a quad-dominant remesh to a target face count with feature preservation (use Blender's built-in QuadriFlow or voxel remesh plus decimation; cite the licence of what you use; no GPL code outside the bridge), optional symmetry, and hard-edge preservation; output is one closed manifold where the input allows.
4. **`rebake`:** bakes base colour, normal (tangent space, with the convention stated), roughness, metallic and ambient occlusion from the dense source to the clean mesh's new UVs with cage or ray distance control, and an optional de-lighting step that divides out low-frequency shading estimated from the source (documented as an estimate).
5. **`import_generated`:** one command that imports a GLB/OBJ, runs diagnose, repair, retopo to a budget, unwrap and rebake, and returns the before and after diagnosis, so an agent can take any generated asset to a judged state in one auditable step; every step's parameters recorded.
6. **Routing, docs and MCP:** metadata, held-out benchmark intents, command reference, a workflow from generated mesh to judged asset, Tier 1 line through the family table.

## Tests

One negative test per acceptance item: a test that fails when the behaviour the item names stops holding. Say how you proved it, for example by breaking the code once and watching the test fail. Fixtures generated by script: a dense noisy mesh with holes, floaters, internal faces, flipped shells, wrong scale and a baked-light albedo. Assert: diagnose finds each defect; repair fixes exactly what it was asked; retopo hits the face budget within a stated tolerance and keeps the silhouette (IoU against the source from the judge's views above a stated value) and Hausdorff distance within a stated share of the size; rebake's normal map reproduces the source's shading within a stated error; the result passes the judge's manifold, degenerate, hidden-ratio, UV and texture rules.

## Rules

- Follow `CONTRIBUTING.md`. No wall-clock bounds in tests.
- **Allowed files:** new bridge modules and commands, `commands/bake.py` and the UV modules where reuse needs it, `src/mcp/routing/families.ts` and routing data, `bench/tool-selection/**`, `test/**`, `bridge/tests/**`, `docs/**`.
- **Files shared with other open jobs:** judge jobs own `src/judge/**` and `bridge/judge/**` (use the judge, do not change it).
- **Environment and concurrency:** Blender 5.2 through `BLENDER`. At most `BLENDWORKS_JOBS` Blender processes at once, 2 by default.
- **While working:** iterate with `npm run check:fast`. Run `npm run check` once, at the end, at low priority.

## Acceptance

1. `npm run check` passes with the patch applied to `main` at the commit the delivery names.
2. Every required item has a test that fails when its behaviour stops holding.
3. The judge takes a CC0 scan from the library at its densest local resolution and a deliberately broken generated-style fixture through `import_generated` to a 10k-triangle budget, judges both with a prop spec, and reviews before/after renders and close-ups.

## Deliver

One commit; the patch from `git format-patch -1 --stdout`. Announce its sha256 to the judge.
