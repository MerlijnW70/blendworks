# Job: Provenance and licences that travel with the asset and can be judged

The asset library records a `LICENSE.json` for every Poly Haven download (asset id, licence, authors, files and hashes), but nothing carries it into the exported asset, and the judge has no licence rule, so a hirer cannot check that a delivery used only CC0 inputs or credit the authors. Glyph outlines used by `engrave` also come from a font with its own licence. Make provenance part of the asset and of the spec.

## Base

- **Base commit:** the `main` commit this spec is added in. Rebase onto the latest `main` before delivering.

## Required

1. **Tracking:** every library asset applied to the scene (HDRI, texture set, model) and every built-in source with a licence (for example glyph fonts) is recorded on the objects, materials and images it reaches, and survives duplication, joining, baking (a baked image inherits the sources of what it baked) and boolean operations.
2. **Export:** glTF export writes `asset.copyright` and an `extras.blendworks_provenance` block (format and version; each source with id, kind, licence identifier and URL, authors, file hashes, and what it was used for) at the asset level, and per node or material where relevant; documented and versioned.
3. **Spec group `licence`:** `allowed` (SPDX identifiers, for example `["CC0-1.0"]`), `requireProvenance` (every texture image and every imported mesh is accounted for by a source or by being procedural), `requireAttribution` (attribution text present for licences that need it). The judge measures it from the delivered file only and treats the provenance block as a claim to verify: image hashes in the file must match the recorded hashes, and an image with no source and no procedural origin fails `requireProvenance`.
4. **Report:** the judge report lists sources and licences, and `blendworks diff` shows changes.
5. **Docs:** the asset spec and judge docs describe the group and its limits (what can and cannot be proven from a file).

## Tests

One negative test per acceptance item: a test that fails when the behaviour the item names stops holding. Say how you proved it, for example by breaking the code once and watching the test fail. Include a forged provenance block whose hashes do not match the embedded images, and an image added after baking with no source.

## Rules

- Follow `CONTRIBUTING.md`. Fixtures are generated by scripts; library downloads in tests use the existing fake server.
- **Allowed files:** `bridge/blendworks_bridge/gltf_extras.py`, the export and library-apply command modules, a new provenance module, `src/mcp/library/**` (apply side), `src/judge/**` and `bridge/judge/**` for the new rule, `schemas/**`, `test/**`, `bridge/tests/**`, `docs/**`.
- **Files shared with other open jobs:** the judge jobs (judge-container, judge-integrity-3) own `src/judge/**` and `bridge/judge/**` until they land; this job starts after them.
- **Environment and concurrency:** Blender 5.2 through `BLENDER`. At most `BLENDWORKS_JOBS` Blender processes at once, 2 by default.
- **While working:** iterate with `npm run check:fast`. Run `npm run check` once, at the end, at low priority.

## Acceptance

1. `npm run check` passes with the patch applied to `main` at the commit the delivery names.
2. Every required item has a test that fails when its behaviour stops holding.
3. The judge builds a scene with a CC0 HDRI, a CC0 texture set and an engraved part, bakes and exports it, judges it with `licence: { allowed: [...], requireProvenance: true }` and sees it pass, then swaps in an untracked image and sees it fail.

## Deliver

One commit; the patch from `git format-patch -1 --stdout`. Announce its sha256 to the judge.
