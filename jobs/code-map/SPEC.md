# Job: Code map — one document that tells a new worker where everything is

Every worker starts by reading tens of files to learn how Blendworks is put together. That costs most of its first hour. Add a generated code map, kept in sync by a check, so that a worker can find the module, function and test they need from one document.

## Base

- **Base commit:** the `main` commit this spec is added in. Rebase onto the latest `main` before delivering.

## Required

1. **`docs/CODEMAP.md`, generated by a script.**
   - A short overview of the layers: MCP server, bridge, commands, judge, tests and scripts.
   - For every bridge module and command: one line on what it does, taken from its docstring; its main public functions; the commands it registers; and the test files that cover it, taken from the existing test map.
   - For TypeScript sources and scripts: one line each.
   - A "how to work" section that says:
     - how to run one bridge test and one vitest file;
     - where examples, renders and limits live;
     - how the shared Blender and the memory gate behave;
     - how to add a command, a limit and a test.
2. **Kept in sync.**
   - A test fails when a module or command is added, removed or renamed without regenerating the map.
   - It also fails when a module has no docstring line.
   - Missing docstrings found during this job are written, briefly and accurately.
3. **Compact.** The map stays under a stated size (for example 60 KB), so it is cheap to read. Details link to the files instead of being copied.

## Tests

One negative test per required item: a test that fails when the behaviour the item names stops holding. Say how you proved it, for example by breaking the code once and watching the test fail.

## Rules

- Follow `CONTRIBUTING.md` and the worker brief.
- **Allowed files:**
  - a new generator script, for example `scripts/codemap.mjs`;
  - `docs/**`;
  - `test/**`;
  - module docstrings in `bridge/**` and `src/**`. Docstring lines only, with no behaviour change.
- **Environment and concurrency:** the machine is shared.

## Acceptance

1. `npm run check` passes on Windows with the patch applied to `main`.
2. Every required item has a test that fails when its behaviour stops holding.
3. A fresh worker given only the map can name the module, function and test for five tasks the judge picks.

## Deliver

One commit; the patch from `git format-patch -1 --stdout`. Announce its sha256 to the judge.
